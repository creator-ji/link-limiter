# Link Limiter

## О проекте

Link Limiter — учебное консольное приложение на Java для создания коротких ссылок. Пользователь может установить лимит переходов и просматривать состояние своих ссылок. После достижения лимита или окончания срока жизни ссылка становится недоступной.

На первом этапе данные хранятся только в памяти и удаляются после завершения приложения.

## Функциональные требования

### Идентификация пользователя

- при первом создании ссылки приложение генерирует пользователю UUID;
- UUID выводится в консоль, чтобы пользователь мог сохранить его;
- пользователь вводит UUID при последующих действиях со своими ссылками;
- авторизация по логину и паролю не используется;
- пользователь может просматривать и удалять только свои ссылки.

UUID идентифицирует пользователя, но не подтверждает его личность. Любой человек, получивший UUID, сможет управлять соответствующими ссылками. Это допустимое ограничение учебной версии.

### Создание короткой ссылки

Пользователь передаёт:

- исходный URL;
- максимальное количество переходов;
- свой UUID, если он был создан ранее.

Приложение должно:

1. Проверить формат URL. Разрешены абсолютные адреса с протоколом `http` или `https`.
2. Проверить, что лимит переходов является положительным целым числом.
3. Создать UUID, если пользователь обращается впервые.
4. Сгенерировать уникальный короткий код.
5. Рассчитать дату окончания срока жизни.
6. Сохранить ссылку и вывести её короткий вариант.

Пример отображаемой ссылки:

```text
clck.ru/3DZHeG
```

Адрес `clck.ru` используется как отображаемый префикс. Локальное консольное приложение не публикует настоящий интернет-адрес: пользователь вводит короткую ссылку или её код в приложении, после чего приложение открывает исходный URL в браузере. Если автоматическое открытие браузера недоступно, исходный URL выводится в консоль.

### Уникальность ссылок

- каждый короткий код должен быть уникальным во всём приложении;
- одинаковый исходный URL, сокращённый разными пользователями, получает разные короткие ссылки;
- повторное сокращение URL тем же пользователем также создаёт новую ссылку с собственными лимитом, сроком жизни и статистикой;
- при совпадении с уже существующим кодом приложение генерирует новый код.

### Лимит переходов

- счётчик начинается с нуля;
- успешный переход увеличивает счётчик на единицу;
- переход с номером, равным установленному лимиту, разрешён;
- после выполнения последнего разрешённого перехода ссылка получает состояние `LIMIT_REACHED`;
- все последующие переходы отклоняются;
- неуспешные попытки не увеличивают счётчик.

Например, при лимите `3` разрешены три перехода. Четвёртый переход отклоняется.

### Срок жизни

- срок жизни задаётся системой и одинаков для всех новых ссылок;
- базовое значение — 24 часа с момента создания;
- пользователь не может изменить срок жизни;
- ссылка доступна, пока текущее время строго меньше `expiresAt`;
- при наступлении `expiresAt` ссылка получает состояние `EXPIRED` и становится недоступной;
- просроченные ссылки удаляются из активного хранилища при обращении к ним и во время периодической очистки.

Для возможности тестирования расчёты времени должны использовать `java.time.Clock`.

### Уведомления

Консольное приложение сообщает владельцу, что:

- лимит переходов исчерпан;
- срок жизни ссылки истёк;
- можно создать новую короткую ссылку.

Уведомления показываются при просмотре списка ссылок или при следующем действии пользователя с его UUID. Внешние уведомления по электронной почте или телефону не предусмотрены, поскольку UUID не содержит контактных данных.

### Управление ссылками

Пользователь может:

- создать короткую ссылку;
- перейти по короткой ссылке;
- просмотреть список собственных ссылок;
- увидеть исходный URL, короткий код, лимит, число переходов, дату окончания и состояние;
- изменить лимит переходов активной ссылки;
- удалить свою ссылку вручную.

## Модель данных

### User

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Уникальный идентификатор пользователя |

### ShortLink

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Внутренний идентификатор ссылки |
| `ownerId` | `UUID` | Идентификатор владельца |
| `originalUrl` | `String` | Исходный URL |
| `shortCode` | `String` | Уникальный короткий код |
| `clickLimit` | `int` | Максимальное число переходов |
| `clickCount` | `int` | Число выполненных переходов |
| `createdAt` | `Instant` | Момент создания |
| `expiresAt` | `Instant` | Момент окончания срока жизни |
| `status` | `LinkStatus` | Текущее состояние |

### Состояния ссылки

| Состояние | Описание |
| --- | --- |
| `ACTIVE` | Срок жизни и лимит ещё не исчерпаны |
| `LIMIT_REACHED` | Выполнено максимальное число переходов |
| `EXPIRED` | Истёк срок жизни |

Допустимые изменения состояния:

```text
ACTIVE -> LIMIT_REACHED
ACTIVE -> EXPIRED
LIMIT_REACHED -> EXPIRED
EXPIRED -> удаление из хранилища
```

Состояния `LIMIT_REACHED` и `EXPIRED` не возвращаются в `ACTIVE`. При ручном удалении ссылка физически исключается из хранилища.

## Хранение данных

Для первой версии используются коллекции в памяти:

- ссылки по короткому коду — для быстрого поиска при переходе;
- ссылки по UUID владельца — для просмотра пользовательского списка;
- использованные короткие коды — для контроля уникальности.
- очередь уведомлений по UUID владельца — чтобы сообщить об удалённой просроченной ссылке при следующем обращении пользователя.

Перед автоматическим удалением просроченной ссылки приложение добавляет уведомление её владельцу. Данные не сохраняются после закрытия приложения. База данных и файловое хранилище на данном этапе не требуются.

## Консольные сценарии

Главное меню:

```text
1. Создать короткую ссылку
2. Перейти по короткой ссылке
3. Показать мои ссылки
4. Удалить ссылку
5. Изменить лимит переходов
h. Справка
0. Выйти
```

### Создание

Пользователь вводит UUID или указывает, что обращается впервые, затем вводит URL и лимит. Приложение возвращает UUID пользователя, короткую ссылку и дату окончания её срока жизни.

### Переход

Пользователь вводит короткую ссылку или код. Приложение проверяет наличие записи, срок жизни и лимит. При успехе увеличивается счётчик и открывается исходный URL. При отказе выводится точная причина.

### Просмотр

Пользователь вводит UUID и получает только свои ссылки со статистикой и состояниями. Здесь же выводятся уведомления об исчерпанном лимите и истёкшем сроке.

### Удаление

Пользователь вводит UUID и короткий код. Удаление выполняется только тогда, когда UUID совпадает с `ownerId`.

### Изменение лимита

Владелец может изменить лимит активной ссылки. Новый лимит должен быть положительным и превышать уже выполненное количество переходов. Изменение чужой, просроченной или уже исчерпавшей лимит ссылки запрещено.

## Обработка ошибок

Приложение должно выводить понятное сообщение и продолжать работу при следующих ситуациях:

- URL пустой, имеет неверный формат или использует протокол, отличный от `http` и `https`;
- лимит не является целым положительным числом;
- UUID имеет неверный формат или не найден;
- короткий код не найден;
- пользователь пытается удалить чужую ссылку;
- лимит переходов исчерпан;
- срок жизни ссылки истёк;
- браузер не поддерживается текущей средой.

## Критерии приёмки

Этап реализации считается завершённым, если:

1. Первый пользователь получает UUID и может создать короткую ссылку.
2. Два пользователя получают разные короткие ссылки для одного исходного URL.
3. Количество успешных переходов не превышает установленный лимит.
4. После окончания 24 часов переход невозможен.
5. Владелец видит уведомление о причине недоступности ссылки.
6. Пользователь видит и удаляет только свои ссылки.
7. Некорректный ввод не завершает приложение аварийно.
8. Основная бизнес-логика покрыта модульными тестами, включая граничные случаи лимита и времени.

## Архитектура

```text
src/main/java/.../
├── config/       загрузка application.properties и системные настройки
├── exception/    ошибки предметной области
├── model/        User, ShortLink, LinkStatus
├── repository/   хранение пользователей и ссылок в памяти
├── service/      бизнес-логика, валидация, разбор ссылок и фоновая очистка
└── ui/           консольное меню и открытие исходного URL в браузере
src/main/resources/
└── application.properties
```

Основные технические решения:

- Maven для сборки проекта;
- Java 17 или более новая совместимая версия;
- параметры TTL, очистки, длины кода и диапазона лимитов читаются из `application.properties`;
- `java.net.URI` для проверки URL;
- `java.time.Clock` и `Instant` для работы со временем;
- `SecureRandom` и алфавит из латинских букв и цифр для коротких кодов;
- JUnit 5 для модульных и интеграционных тестов;
- Spotless + `.editorconfig` для форматирования;
- GitHub Actions для сборки, тестов и проверки стиля;
- бизнес-логика не зависит от консольного интерфейса.

### Модули проекта

- `App` — точка входа, создание зависимостей и управление жизненным циклом фоновой очистки.
- `config` — `ConfigLoader` и `AppConfig`: чтение `application.properties`.
- `model` — пользователь, короткая ссылка и состояния ссылки.
- `repository` — интерфейсы хранилищ и их потокобезопасные реализации в памяти.
- `service` — создание и использование ссылок, проверка URL, разбор короткого кода, генерация кода и очистка просроченных записей.
- `ui` — консольное меню, справка и открытие исходного URL в браузере.
- `exception` — ошибки предметной области с понятными сообщениями.
- `src/test` — модульные и интеграционные тесты модели, конфигурации, репозитория, валидации, CLI и бизнес-логики.

## Конфигурация

Ключевые параметры находятся в [`src/main/resources/application.properties`](src/main/resources/application.properties):

```properties
short.link.prefix=clck.ru/
link.lifetime.hours=24
cleanup.interval.minutes=1
short.code.length=6
click.limit.min=1
click.limit.max=1000000
```

Чтобы изменить TTL, интервал очистки, длину кода или допустимый диапазон лимитов, отредактируйте этот файл и перезапустите приложение.

## Запуск

Для работы необходимы JDK 17 и Maven 3.8 или новее.

### Установка

Проверьте установленные версии:

```bash
java -version
mvn -version
```

Загрузите проект и перейдите в его каталог:

```bash
git clone https://github.com/creator-ji/link-limiter.git
cd link-limiter
```

Внешние зависимости:

- JUnit 5 — только для тестов;
- Spotless Maven Plugin — для проверки форматирования в CI и локально.

Maven автоматически загружает их при `mvn test` / `mvn spotless:check`; отдельная ручная установка библиотек не нужна.

### IntelliJ IDEA

1. Открыть корневую папку проекта.
2. Разрешить IntelliJ IDEA импортировать `pom.xml` как Maven-проект.
3. Запустить метод `main` в классе `com.linklimiter.App`.

### Командная строка

### Тестирование

```bash
mvn clean test
```

Проверка форматирования:

```bash
mvn spotless:check
```

Автоматическое форматирование:

```bash
mvn spotless:apply
```

Автоматические тесты проверяют:

- уникальные короткие ссылки для разных пользователей с одинаковым исходным URL;
- разрешение последнего допустимого перехода и блокировку следующего;
- уведомление владельца об исчерпании лимита;
- доступность ссылки за секунду до окончания срока жизни;
- удаление ссылок со сроком жизни 1 час и 24 часа;
- компонент автоматической очистки просроченных ссылок;
- уведомление владельца об истечении срока жизни;
- запрет изменения и удаления чужой ссылки;
- обработку неверного URL и неположительного лимита;
- загрузку параметров из `application.properties`;
- интеграционный CLI-сценарий создания, просмотра и перехода.

## Инструкция пользователя

### Создание первой ссылки

1. Выберите пункт `1`.
2. Оставьте UUID пустым, поскольку пользователь создаётся впервые.
3. Введите полный URL, начинающийся с `http://` или `https://`.
4. Введите положительный лимит переходов.
5. Сохраните выданный UUID: он потребуется для просмотра, изменения и удаления ссылок.
6. Сохраните короткую ссылку, которую покажет приложение.

### Создание следующих ссылок

Выберите пункт `1` и введите ранее сохранённый UUID. Для одного исходного URL можно создать несколько независимых коротких ссылок.

### Переход

Выберите пункт `2` и введите короткую ссылку или только её код. Приложение увеличит счётчик и попытается открыть исходный URL в браузере. Если браузер недоступен, исходный адрес будет показан в консоли.

### Просмотр и уведомления

Выберите пункт `3` и введите UUID. Приложение покажет принадлежащие пользователю ссылки, статистику и уведомления об исчерпанном лимите или истёкшем сроке жизни.

### Удаление и изменение лимита

- пункт `4` удаляет ссылку;
- пункт `5` изменяет лимит переходов активной ссылки;
- для обеих операций нужно ввести UUID владельца;
- новый лимит должен превышать уже выполненное количество переходов.

Срок жизни устанавливается программой и по умолчанию равен 24 часам. Все данные хранятся в памяти и теряются после завершения приложения.
